# Clinical RAG

**Интеллектуальный сервис поиска и формирования ответов по медицинской документации на основе Retrieval-Augmented Generation (RAG).**

Clinical RAG - программный прототип системы поддержки информационного поиска по медицинским документам и клиническим рекомендациям. Сервис объединяет обработку документов, семантический поиск, языковую модель GigaChat и хранение данных в облачной инфраструктуре.

## 1. Назначение проекта

Цель проекта - разработка сервиса, который сокращает время поиска релевантной медицинской информации в документации.

Вместо поиска по полным текстам документов система извлекает наиболее подходящие фрагменты и передаёт их языковой модели для формирования ответа на основе найденного контекста.

Проект ориентирован на исследование и разработку инструментов информационной поддержки медицинских специалистов.

## 2. Основные возможности

- Загрузка документов через API.
- Извлечение текста из документов.
- Разбиение текстов на фрагменты (чанки).
- Получение векторных представлений (эмбеддингов).
- Семантический поиск релевантных фрагментов.
- Формирование ответов с использованием GigaChat.
- Работа с ClickHouse.
- Интеграция с S3-совместимым объектным хранилищем.
- Веб-интерфейс для взаимодействия с сервисом.
- Проверка работоспособности и автоматизированное тестирование.

## 3. Принцип работы RAG

RAG (Retrieval-Augmented Generation) - подход, при котором языковая модель получает дополнительный контекст из внешней базы документов перед формированием ответа.

Основной процесс:

1. Пользователь загружает документ.
2. Сервис извлекает текст.
3. Текст разбивается на небольшие смысловые фрагменты.
4. Для фрагментов рассчитываются эмбеддинги.
5. Информация индексируется и сохраняется в предусмотренных хранилищах.
6. Пользователь отправляет вопрос.
7. Сервис выполняет поиск релевантных фрагментов.
8. Найденный контекст передаётся GigaChat.
9. Модель формирует ответ с опорой на предоставленный контекст.

## 4. Архитектура проекта

Проект разделён на несколько функциональных уровней:

- **API:** обработка запросов и взаимодействие с клиентом.
- **Обработка документов:** извлечение текста, разбиение на фрагменты и подготовка данных.
- **Поиск:** получение эмбеддингов и извлечение релевантного контекста.
- **Генерация:** формирование ответа с использованием GigaChat.
- **Хранение:** взаимодействие с ClickHouse и объектным хранилищем.
- **Frontend:** пользовательский интерфейс.

## 8. Локальный запуск

### Требования

- Python 3.12 или совместимая версия.
- Docker Desktop.
- Git.
- Доступ к необходимым внешним API и хранилищам.

### Шаг 1. Клонирование репозитория

```powershell
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```

Вместо USERNAME и REPOSITORY укажите адрес созданного GitHub-репозитория.

### Шаг 2. Создание виртуального окружения

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### Шаг 3. Установка зависимостей

```powershell
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### Шаг 4. Настройка окружения

Создайте локальный файл `.env` на основе шаблона:

```powershell
Copy-Item .env.example .env
```

Заполните его собственными параметрами подключения.

Для работы интеграций могут потребоваться:

- GigaChat API;
- сервис эмбеддингов Cloud.ru;
- S3 Object Storage;
- ClickHouse.

Не публикуйте `.env`, пароли и API-ключи в открытом репозитории.

### Шаг 5. Запуск ClickHouse

```powershell
docker compose up -d clickhouse
```

Локальная конфигурация ClickHouse использует Docker volume `clickhouse_data` для сохранения данных между пересозданиями контейнера.

### Шаг 6. Запуск API

```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

После запуска доступны:

- http://localhost:8000
- http://localhost:8000/docs
- http://localhost:8000/health

## 9. Docker

Сборка образа:

```powershell
docker build -t clinical-rag-api:latest .
```

Запуск:

```powershell
docker run --env-file .env -p 8000:8000 clinical-rag-api:latest
```

Для сборки Docker-образа необходим каталог `certs` с используемыми сертификатами, поскольку он предусмотрен в Dockerfile. Сертификаты не входят в публичный репозиторий.

## 10. Тестирование

Для запуска автоматизированных тестов:

```powershell
python -m pytest -v
```

Тестовые сценарии расположены в каталоге `tests/`.

## 11. Безопасность

- Секретные параметры хранятся в локальном `.env`.
- `.env` исключён из Git.
- `.env.example` содержит шаблон конфигурации.
- Локальные сертификаты, документы и журналы исключены из публичной публикации.
- Для реального медицинского применения необходимы отдельная проверка информационной безопасности и экспертная медицинская валидация.

## 12. Ограничения

Clinical RAG является исследовательским программным прототипом.

Сервис предназначен для поиска и информационной поддержки при работе с медицинской документацией. Он не заменяет врача, клиническое мышление и профессиональную оценку информации.

Ответы языковой модели требуют проверки специалистом. Перед использованием в реальной медицинской практике необходимы дополнительные испытания и валидация.
